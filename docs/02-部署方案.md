## 0. 资源分配

| 项目 | 端口 | 目录 | 堆 | 说明 |
|---|---|---|---|---|
| setbook（已有） | 8080 / 80 | `/opt/setbook` | 512m | 不动 |
| **shortand（本项目）** | **8081（后端）/ 8082（Nginx）** | **`/opt/shortand`** | **256m** | 后端只监听 `127.0.0.1` |

- 共用现有 MySQL 8.0.46，**不装第二个 MySQL**。
- Nginx 新开 **8082** 端口，不和 setbook 的 80 抢路径。
- **不用 Redis、不用 SnailJob**；Sa-Token 默认内存存储，重启后重新登录。
- 预计新增内存 280–350MB；上线后 `free -m` 的 `available` 保持在 150MB 以上。

## 2. MySQL：建库、建用户

用 root 执行（密码换成强密码，不要和 setbook 一样）：

```sql
CREATE DATABASE IF NOT EXISTS `shortand`
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'shortand'@'127.0.0.1' IDENTIFIED BY '<强密码>';
GRANT ALL PRIVILEGES ON `shortand`.* TO 'shortand'@'127.0.0.1';
FLUSH PRIVILEGES;
```

首次导入表结构（root 执行，脚本里有 `CREATE DATABASE`）：

```bash
# 先把 db/schema.sql 传到服务器
# scp db/schema.sql root@47.95.66.191:/opt/shortand/db/schema.sql
mysql -uroot -p < /opt/shortand/db/schema.sql
```

验证：

```bash
mysql -ushortand -p -e 'use shortand; show tables;'
```

连接串：

```
jdbc:mysql://127.0.0.1:3306/shortand?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
```

连接池：`maximum-pool-size=6`，`minimum-idle=2`。

## 6. Nginx：`/etc/nginx/conf.d/shortand.conf`

```nginx
server {
    listen 8082;
    server_name _;

    root /opt/shortand/web;
    index index.html;
    client_max_body_size 12m;

    gzip on;
    gzip_min_length 1024;
    gzip_types text/plain text/css application/json application/javascript image/svg+xml;

    # 后端 API（用户端 /api，管理端 /api/admin）
    location /api/ {
        proxy_pass http://127.0.0.1:8081;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    # 反馈截图等上传文件，Nginx 直接读磁盘
    # ^~ 不能省，否则会被下面的静态资源正则抢走
    location ^~ /uploads/ {
        alias /opt/shortand/data/uploads/;
        expires 7d;
        add_header Cache-Control "public";
        access_log off;
    }

    # 管理后台 SPA（Vue Router history 模式，base=/admin/）
    location = /admin {
        return 301 /admin/;
    }

    location ^~ /admin/ {
        try_files $uri $uri/ /admin/index.html;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|webp|svg|ico|woff2?|ttf)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
        access_log off;
    }

    # 用户端 SPA
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

```bash
nginx -t && systemctl reload nginx
```

> 访问：`http://47.95.66.191:8082/`（用户端）、`/admin/`（管理端）。

## 8. GitHub Actions：`.github/workflows/deploy.yml`

仓库 Secrets：`DEPLOY_HOST`、`DEPLOY_USER`、`DEPLOY_SSH_KEY`（复用 setbook 的 deploy 用户和私钥）。

```yaml
name: deploy-shortand

on:
  push:
    branches: [main]
  workflow_dispatch:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '17'
          cache: maven

      - name: Build server
        working-directory: server
        run: mvn -B -DskipTests package

      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: npm
          cache-dependency-path: |
            app/package-lock.json
            admin/package-lock.json

      - name: Build app
        working-directory: app
        env:
          VITE_API_BASE: /api
        run: npm ci && npm run build

      - name: Build admin
        working-directory: admin
        env:
          VITE_BASE: /admin/
        run: npm ci && npm run build

      - name: Assemble
        run: |
          mkdir -p deploy/web/admin
          cp -r app/dist/* deploy/web/
          cp -r admin/dist/* deploy/web/admin/
          cp server/target/*.jar deploy/server.jar

      - uses: actions/upload-artifact@v4
        with:
          name: shortand-dist
          path: deploy

  deploy:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/download-artifact@v4
        with:
          name: shortand-dist
          path: deploy

      - name: Upload to server
        uses: appleboy/scp-action@v0.1.7
        with:
          host: ${{ secrets.DEPLOY_HOST }}
          username: ${{ secrets.DEPLOY_USER }}
          key: ${{ secrets.DEPLOY_SSH_KEY }}
          source: "deploy/*"
          target: "/home/deploy/upload-shortand"
          strip_components: 1

      - name: Restart & health check
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.DEPLOY_HOST }}
          username: ${{ secrets.DEPLOY_USER }}
          key: ${{ secrets.DEPLOY_SSH_KEY }}
          script: |
            set -e
            cd /home/deploy/upload-shortand
            chmod 644 server.jar
            chmod -R a+rX web

            cp /opt/shortand/releases/server.jar /opt/shortand/releases/server.jar.prev 2>/dev/null || true
            cp server.jar /opt/shortand/releases/server.jar
            rsync -a --delete web/ /opt/shortand/web/

            sudo systemctl restart shortand

            for i in $(seq 1 45); do
              if curl -fsS http://127.0.0.1:8081/actuator/health >/dev/null; then
                echo "healthy"
                exit 0
              fi
              sleep 2
            done

            echo "health check failed, rollback"
            if [ -f /opt/shortand/releases/server.jar.prev ]; then
              cp /opt/shortand/releases/server.jar.prev /opt/shortand/releases/server.jar
              sudo systemctl restart shortand
            fi
            exit 1
```

> 构建全部在 GitHub Runner 上做，**绝不在 2G 服务器上跑 `mvn package` / `npm build`**。

  | gzip > /opt/shortand/data/backup/shortand-$DAY.sql.gz

## 13. 与 setbook 共存的坑

| 坑 | 本项目的做法 |
|---|---|
| 装第二个 MySQL | 共用 3306，只建 `shortand` 库和用户 |
| 内存抢占 | `-Xmx256m`，`MemoryMax=420M`，SerialGC |
| UFW 未放行 | 只加 `8082/tcp`，8081 不对外 |
| 上传目录混用 | `/opt/shortand/data/uploads` 独立 |
| Nginx 正则抢 `/uploads/` | `location ^~ /uploads/` |
| 在服务器构建 | GitHub Actions 构建，服务器只收产物 |
| JWT 密钥复用 | 独立 `APP_JWT_SECRET` |
| deploy 无 sudo | 单独 sudoers 文件 |
| 管理端刷新 404 | `base=/admin/` + `try_files ... /admin/index.html` |

## 14. 监控红线

| 信号 | 处理 |
|---|---|
| `available` 长期 < 150M | 升级 2C4G |
| swap 持续增长 > 1G | 同上 |
| `journalctl -k \| grep -i oom` 有记录 | 立即处理 |
| 磁盘 > 80% | 清 `data/uploads`、清 7 天前备份 |
| 8081 健康检查连续失败 | 看 `journalctl -u shortand -n 100`，必要时回滚 jar |

## 15. 说明

- **无域名**：先用 `http://47.95.66.191:8082`，iOS 需要 ATS 例外、Android 需要 cleartext；以后有域名再切 HTTPS，Nginx 加 443 即可。
- **读音/TTS 暂不做**：`data/uploads` 只放反馈截图，后续加读音时再建 `word_audio` 表和 `/uploads/audio/`。
- **项目名**：仓库、包名、数据库、目录、systemd 全部用 `shortand`；界面显示名为「神也背单词」。
