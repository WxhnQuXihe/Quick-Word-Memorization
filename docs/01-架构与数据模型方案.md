## 1. 交互规则（最终版）

### 1.1 一组 10 词

- 进入词书 → 取当前未完成的一组；没有就新建。
- 用户自己决定看多久，看完直接点「下一组」。
- 不设每日目标、不设复习队列、不按时间推词。

### 1.2 熟词 → 立即随机替换

```
点击某张卡的「熟词」
  → user_word.is_known = 1
  → 从本书"未标熟、且不在当前组"的词里随机抽 1 个
  → 替换该卡片 position，返回新词
  → 若全书没有可替换的词：该位置置空，提示"本书已全部标熟"
```

- 替换同步返回，前端只换这一张卡，不刷新整组。
- 随机范围是同一本词书，不跨书。
- 被替换的熟词进熟词本；熟词本里"移出"后回到待背池。
- 收藏不触发替换。

### 1.3 「下一组」两段式防误触

| 步骤 | 按钮 | 行为 |
|---|---|---|
| 第 1 次点击 | 文案变「再点一次进入下一组」，警示色，3 秒倒计时 | 只进入待确认，不发请求 |
| 3 秒内第 2 次点击 | 调 `POST /api/study/group/{id}/next` | 本组完成，返回下一组 |
| 3 秒超时 | 恢复「下一组」 | 取消确认 |

请求中按钮置灰；后端对已完成组再次 `next` 直接返回当前进行中的组（幂等）。

### 1.4 单词/释义隐藏（单卡 + 全局都保留）

- 每张卡分两个点击区：单词区、释义区。
- 点单词区只隐藏该卡的单词（含音标），释义仍显示；再点恢复。
- 点释义区只隐藏该卡的释义，单词仍显示；再点恢复。
- 每张卡独立，纯前端状态，不落库。
- **底部操作栏保留全局按钮**：「隐藏单词」「隐藏释义」「下一组」。
  - 点「隐藏单词」：本组所有卡的单词一次性隐藏，按钮变「显示单词」；再点全部显示。
  - 点「隐藏释义」：同理，按钮变「显示释义」；再点全部显示。
  - 全局按钮只做批量切换；之后仍可单卡点开某一个，单卡状态和全局按钮互不覆盖。
  - 按钮文案按"当前是否全部隐藏"计算：全部隐藏时显示「显示单词 / 显示释义」，否则显示「隐藏单词 / 隐藏释义」。
- 熟词/收藏按钮 `stopPropagation`，避免误触隐藏。

### 1.5 v1 不做的

每日目标、连续打卡、遗忘曲线、复习队列、读音/TTS、例句朗读、跟读评分、社区、支付、注册。

## 3. 学习模型

### 3.1 轮次 + 组

- **一轮** = 把词书里"未标熟"的词按书内顺序过一遍。
- **一组** = 一轮中的 10 个词；最后一组可能不足 10。
- 一轮过完 → 下一组自动进入下一轮（`round_no + 1`），从第 1 个词重新过（熟词永久排除）。
- 轮次只是"从头再刷"的边界，不做任何时间/记忆调度。

### 3.2 取词规则

**当前组**：

1. 查 `user_wordbook`，没有就创建，`current_round_no = 1`。
2. 查该书当前轮次有没有 `status = 0` 的组；有就返回。
3. 没有就新建：
   - 取本书 `seq` 升序、`is_known = 0`、且**不在本轮任何组**里的前 10 个词；
   - 取不到 → `current_round_no + 1`，重新取；
   - 还取不到 → 全书已熟，返回 `finished`；
   - 写入 `study_group` + `study_group_word`，给这 10 个词 `seen_count + 1`。

**下一组**：

1. 当前组 `status = 1, finish_time = now`；
2. 取下一组，`group_no = 当前轮最大组号 + 1`；
3. 本轮取完 → 进入下一轮，`group_no = 1`；
4. 没有词了 → `finished`。

**熟词替换**：

1. 校验词在当前组；
2. `user_word.is_known = 1, known_time = now`；
3. 随机取 1 个：本书、`is_known = 0`、不在当前组（可以来自本轮之前的组，算复习）；
4. 有 → 更新该 `position` 的 `word_id`，`seen_count + 1`，返回新词；
5. 无 → 该位置 `status = 2, word_id = NULL`，返回空。

> 替换词允许来自本轮已刷过的组，保证"熟词换新词"尽量换得到；"下一组"取词会排除本轮所有组，保证一轮内不重复推进。

### 3.3 进度

- 词书进度 = 本书 `user_word.seen_count > 0` 的词数 / `wordbook.word_count`。
- 收藏数 / 熟词数 = `user_word` 全局计数，主页、我的、收藏夹、熟词本同源。
- 不做今日目标/打卡；主页只显示当前词书进度、收藏数、熟词数、继续背。

## 4. 数据库（11 张表）

| # | 表 | 作用 |
|---|---|---|
| 1 | `app_user` | 用户（后台创建，不开放注册） |
| 2 | `wordbook` | 词书（四级/六级/词组） |
| 3 | `word` | 全局词条 |
| 4 | `wordbook_word` | 词书-词关联、书内顺序 |
| 5 | `user_wordbook` | 用户书架、当前轮次 |
| 6 | `study_group` | 学习组（10 词/组） |
| 7 | `study_group_word` | 组内 position 1~10 与当前词 |
| 8 | `user_word` | 收藏 / 熟词 / 见过次数 |
| 9 | `feedback` | 意见反馈 |
| 10 | `admin_user` | 管理员（单账号） |
| 11 | `import_log` | Excel 导入记录 |

- 收藏夹、熟词本不建表：`user_word.is_favorite / is_known` 两个标志位。
- 不建统计表：进度和计数直接算，个人使用量级完全够。
- 字符集 `utf8mb4_unicode_ci`，与 setbook 一致。
- 不做 `word_audio`，读音以后再加。

### 4.1 多词性释义

一个词有多个词性时，**不拆新表，也不合成一段**：

- `word.pos` 存首个词性（兼容旧逻辑，可空）。
- `word.meaning` 用换行分隔，一行一个词性：

```
v. 放弃；遗弃；离开；终止
n. 放任；狂热
```

- 后端 `WordVo` 把它拆成 `senses: [{pos, meaning}]` 返回；前端只负责渲染，不解析字符串。
- 导入模板的「释义」单元格同样一行一个词性；PDF 清洗脚本负责把 `v. … n. …` 拆行。
- 这样不用加表、不用改 SQL，管理后台也只是一个多行文本框。

DDL 见 `db/schema.sql`。**它只在首次部署时执行一次，业务代码里不出现任何 SQL。**

### 5.1 零 SQL 的写法

- 查询一律 `LambdaQueryWrapper` / `QueryWrapper`，**不写 XML、不写 `@Select`**。
- 取当前组/下一组/随机替换，不写子查询 SQL：先把"本书全部 wordId（按 seq 排序）"、"本轮已用 wordId"、"已熟 wordId"三组 ID 查出来，在 Java 里做集合差，再取前 10 或随机 1 个。词书最大 5515 条，内存完全够。
- 批量写用 `saveBatch(list, 500)`。
- 分页用 `Page<T>` + `PaginationInnerInterceptor`。
- 逻辑删除用 `@TableLogic`。

示例（熟词随机替换，纯 Wrapper + Java）：

```java
// 1. 本书按 seq 排序的全部 wordId
List<Long> bookWordIds = wordbookWordMapper.selectList(
        Wrappers.<WordbookWord>lambdaQuery()
                .eq(WordbookWord::getWordbookId, wordbookId)
                .orderByAsc(WordbookWord::getSeq))
        .stream().map(WordbookWord::getWordId).toList();

// 2. 已熟 wordId
Set<Long> knownIds = userWordMapper.selectList(
        Wrappers.<UserWord>lambdaQuery()
                .eq(UserWord::getUserId, userId)
                .eq(UserWord::getIsKnown, 1))
        .stream().map(UserWord::getWordId).collect(Collectors.toSet());

// 3. 当前组已有 wordId
Set<Long> groupIds = studyGroupWordMapper.selectList(
        Wrappers.<StudyGroupWord>lambdaQuery()
                .eq(StudyGroupWord::getGroupId, groupId))
        .stream().map(StudyGroupWord::getWordId)
        .filter(Objects::nonNull).collect(Collectors.toSet());

// 4. 候选 = 本书 - 已熟 - 当前组，随机取一个
List<Long> candidates = bookWordIds.stream()
        .filter(id -> !knownIds.contains(id) && !groupIds.contains(id))
        .toList();
Long replacementId = candidates.isEmpty() ? null
        : candidates.get(ThreadLocalRandom.current().nextInt(candidates.size()));
```

> 这就是"尽量不写 SQL"的落地方式：DB 只做简单条件查询，业务筛选放 Service。

### 5.2 一个业务对象的 7 个文件

`WordbookController`、`Wordbook`、`WordbookBo`、`WordbookVo`、`WordbookMapper`、`IWordbookService`、`WordbookServiceImpl`，加可选 `WordbookMapper.xml`——本项目**不需要 XML**。

### 5.3 泛型

- Mapper 直接 `extends BaseMapper<Wordbook>`，不用 `BaseMapperPlus<Xxx, XxxVo>`；
- Service 全部具体类型，不写 `IBaseService<T>`；
- 转换用 `BeanUtil.copyProperties` 或手写 `toVo()`。
